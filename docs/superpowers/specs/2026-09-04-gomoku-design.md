# BbPet 五子棋对局

好友之间下一盘无禁手五子棋。校长当裁判，独立小窗下棋，学校里的人还在原地。

## 背景

学校、好友、串门已经能用。`docs/v2-meeting-room.md` 把五子棋标在 v2.3（邀请 → 确认 → overlay → 服务端状态机）。当前协议没有 `inviteGame` / `gameMove`，点同学只能加好友或去他家。

这一刀做好友对弈，不做人机、不把人迁进 `game:` 房间、不做桌宠邀请气泡。猜拳、麻将不在范围里。

## 目标

两名在线好友能：从好友列表或学校点人发出邀请 → 对方接受 → 两边弹出棋盘窗 → 下完一局（五连、满盘、认输、超时或断线）→ 关掉窗口。

成功标准：

- 邀请方执黑，15×15，无禁手，五连或长连即胜。
- 每步 30 秒，超时判负；倒计时两边看到的是同一个截止时间。
- 非法落子被校长拒绝，本地棋盘不乱跳。
- 一人同时只有一局（含待处理邀请）。

## 规则

- 棋盘：15×15 交叉点，不是格子中心。
- 黑先。邀请方执黑，接受方执白。
- 横、竖、两斜任意方向连续 ≥5 子获胜（长连算赢）。
- 无三三、四四、长连禁手。
- 盘满且无人五连：平局。
- 认输、关进行中的棋盘窗、本步超时、断线超过 30 秒：对方胜。

不提供悔棋、和棋申请、加时、让子。

## 架构

规则是纯函数；对局状态只在校长进程；窗口只显示和点选。

```
好友面板 / 学校点好友
        │ inviteGame
        ▼
桌宠主进程 ──WS──► 校长（对局表 + shared/gomoku.ts）
        ▲                    │
        │ gameState          │ 到期判负
棋盘小窗 ◄── IPC ◄───────────┘
```

- 不引入 Phaser / 3D / 新服务器进程。
- 不修改 `placeId`。对局期间学校/家坐标照常，人不会从地图消失。
- 棋谱不写磁盘。校长重启则进行中的局丢失。

## 组件

| 单元 | 职责 | 依赖 |
| --- | --- | --- |
| `shared/gomoku.ts` | 棋盘、落子、五连/满盘判定 | 无 |
| `shared/world.ts` | 对局报文与 `GameView` 类型 | gomoku 的棋盘表示 |
| 校长对局表（`roomServer` 内或抽出的模块） | 邀请、回合、截止时间、一人一局 | gomoku + 好友关系 + 在线表 |
| `electron/main.ts` 的 `gameWin` | 开/关 hash `#game` 的不透明小窗；进行中关窗发 `gameResign` | roomClient |
| `src/game/GomokuApp.tsx` | 画棋盘、倒计时、认输/结果 | `gameState` |
| `FriendsPanel` | 「五子棋」按钮 + 邀请条 | `inviteGame` / `gameRespond` |
| `WorldApp` 点人菜单 | 已是好友时多「五子棋」；顶栏接受/拒绝 | 同上 |

倒计时不放进 `gomoku.ts`。截止时间戳由校长写入 `GameView.deadlineAt`，客户端只用来显示。

## 界面

### 入口

- 好友列表：对方在线、不是自己、双方都不在局里 → 「五子棋」。
- 学校：点已是好友的同学，菜单加「五子棋」，条件同上。
- 家里客厅、桌宠气泡：不做。

收到邀请：

- 好友面板顶部：来自谁、剩余时间、接受、拒绝。
- 若学校窗开着：顶栏同样两个按钮。
- 只盯着桌宠、两个面板都没开：邀请在 60 秒后自行消失，没有桌面气泡。

### 棋盘窗

普通不透明小窗（与学校窗同类，不是桌宠透明置顶），hash `#game`。

- 标题区：对手名字、你执黑/白、轮到谁、倒计时秒数。
- 棋盘：像素木纹、15×15 线、子落在交叉点；上一步高亮；胜局画出那条五连。
- 不是你的回合点不到。
- 进行中：认输按钮。提示「关闭窗口 = 认输」。
- 结束后：你赢了 / 你输了 / 平局，以及原因（五连、满盘、对方认输、对方超时、对方断线）。棋盘保留。按钮改为关闭。再关窗不再发 `gameResign`。

同一客户端同时只开一扇棋盘窗。主进程只在 `status` 变为 `playing` 时打开棋盘窗；已有窗则聚焦。重连时若仍是 `playing` 则打开；`pending` 或 `ended` 不自动开窗。

## 协议

接到现有 WebSocket JSON，不另开端口。

客户端 → 校长：

| 报文 | 字段 | 何时 |
| --- | --- | --- |
| `inviteGame` | `targetId` | 点「五子棋」 |
| `gameRespond` | `gameId`, `accept` | 接受或拒绝 |
| `gameMove` | `gameId`, `x`, `y` | 点交叉点，坐标整数 0–14 |
| `gameResign` | `gameId` | 认输或关掉进行中的棋盘窗 |

校长 → 客户端：权威快照 `gameState { game: GameView }`。邀请出现、开局、落子、超时、结束都走它。非法操作回现有 `error`，不改棋盘。短提示用现有 `notice`。

`roomClient` 把最新 `game` 写进 `RoomView.game`（无局时为 `null`）。好友面板、学校窗、棋盘窗都读这一份，用来显示邀请条、禁用「已经在下」的按钮、以及决定是否打开棋盘窗。

`GameView`：

- `id`
- `status`: `pending` \| `playing` \| `ended`
- `black` / `white`：`clientId`, `name`, `species`, `colors`（`pending` 且尚未接受时，白方用被邀请人名片）
- `board`: 15×15，`board[y][x]`，`(0,0)` 在左上，`x` 向右、`y` 向下。`0` 空、`1` 黑、`2` 白
- `turn`: `1` \| `2`（仅 `playing` 有意义）
- `deadlineAt`: Unix 毫秒。`pending` 是邀请过期时刻；`playing` 是本步超时时刻
- `lastMove`: `{ x, y }` 或 `null`
- `winLine`: 连成胜利的那串坐标（至少 5 个），或 `null`
- `result`: `null`，或 `{ winnerId: string \| null, reason }`。平局时 `winnerId` 为 `null`。`reason` 为 `five` \| `draw` \| `resign` \| `timeout` \| `disconnect` \| `expired` \| `declined`
- `you`: 本端视角 `black` \| `white`（被邀请方在 `pending` 时也是 `white`）

`welcome` 若该 `clientId` 仍有 `pending` 或 `playing` 局，必须带上当前 `game`：`playing` 用来恢复棋盘窗，`pending` 用来恢复邀请条。

## 对局生命周期

1. **邀请。** 校验：`targetId` 是好友、双方在线、都不是自己、双方都没有 `pending`/`playing`。失败则 `error`，不建局。成功则建局 `pending`，`deadlineAt = now + 60s`，两边推 `gameState`。邀请方不弹棋盘窗。
2. **应答。** 接受 → `playing`，空盘，`turn = 1`，`deadlineAt = now + 30s`。两边主进程打开棋盘窗。拒绝或 60 秒未答 → `ended`，`reason` 为 `declined` 或 `expired`，`winnerId = null`。邀请方 `notice`，不弹窗。
3. **落子。** 必须是你的颜色、当前回合、空点、坐标 0–14、`status === playing`。校长调用 `gomoku` 落子并判胜/满盘。未结束则换手，`deadlineAt = now + 30s`。
4. **回合定时器。** 每次进入新回合（含开局）时，校长 `setTimeout` 到 `deadlineAt`。回调里若仍是同一 `gameId`、同一 `turn`、仍是 `playing` → 当前行棋方负，`reason: timeout`。落子或结束时清掉旧定时器。
5. **断线。** `playing` 中一方断开：启动 30 秒宽限。同 `clientId` 在宽限内 `hello` 成功则继续，倒计时仍用原来的 `deadlineAt`（可能一回来就已经超时）。宽限结束仍不在线 → 断线方负，`reason: disconnect`。`pending` 期间任一方断开 → 局作废，等同邀请过期，不判胜负。
6. **认输。** 仅 `playing` 接受 `gameResign`。关棋盘窗时主进程在 `playing` 下发 `gameResign`。
7. **一人一局。** 已有 `pending`/`playing` 时再 `inviteGame` 或再被邀，直接 `error`。`ended` 后可以马上开新局。

客户端倒计时用 `deadlineAt` 与本地时钟显示秒数，**不以本地到 0 作为判负依据**。若本地已显示 0 但尚未收到结束快照，棋盘进入等待校长确认的状态，不允许再点。

## 错误处理

用户可见失败走 `error` / `notice`，棋盘保持上一份合法快照。

| 情况 | 行为 |
| --- | --- |
| 不是好友 | 「先加好友再下棋」 |
| 对方离线 | 「对方不在线」 |
| 邀请自己 | 「不能和自己下」 |
| 已在局里 | 「已经在下棋了」 |
| 邀请过期或被拒 | 邀请方 `notice`，不打开棋盘窗 |
| 不是你的回合 / 点已有子 / 越界 / 局已结束 | `error`，忽略这次点击 |
| `gameRespond` / `gameMove` / `gameResign` 的 `gameId` 不存在或不属于你 | `error`，忽略 |
| 校长重启 | 内存局丢失；重连后没有 `game`，若棋盘窗还开着则提示「对局已中断」并关闭 |
| 掉线 30 秒内重连 | `welcome` 带回同一局 |
| 关已结束的棋盘窗 | 只关窗 |

报文缺字段或类型不对：现有「报文看不懂」路径。

## 测试

先测纯规则和状态机，不启 Electron。

`shared/gomoku.ts`：

- 横、竖、两斜五连胜
- 六连及以上也胜
- 四连及以下不胜
- 满盘且无五连 → 平
- 已占点、越界 → 落子失败
- 空盘、单子 → 无胜者

校长对局表（抽出可测模块，不直接绑 `ws`）：

- 非好友 / 离线 / 自己 → 不建局
- 接受后邀请方执黑、空盘、轮到黑
- 拒绝、邀请超时 → `declined` / `expired`
- 非法落子被拒，盘面不变
- 模拟时间前进 30 秒 → 当前方 `timeout` 负
- 认输 → 对方胜
- 已有局时第二次邀请失败
- `playing` 断线超过 30 秒 → `disconnect`

手动验收：

- 好友列表邀请 → 接受 → 下出五连
- 学校点好友邀请 → 拒绝
- 进行中关掉棋盘窗 → 对方看到认输胜
- 不是自己回合点击无效果

## 明确不做

- 悔棋、围观、人机、让子、积分排行
- 连珠禁手、19×19、棋钟（仅每步 30 秒）
- 桌宠邀请气泡、家里客厅入口
- 把玩家 `placeId` 改成 `game:{id}`
- 持久化棋谱、校长重启后恢复
- Phaser / 新端口 / 新进程

## 和 v2 规划的差异

v2 原文是世界窗 overlay，并把人放进 `game:{id}`。实现改为独立棋盘窗，学校位置不动。邀请入口是好友列表 + 学校点好友，不做桌面气泡。猜拳不在这一刀。
